# 🏛️ TamakKG — Архитектурная Спецификация Системы (ARCHITECTURE.md)
> **Статус**: Действующий единый источник правды (Single Source of Truth)  
> **Версия**: 2.0 (Modern Spec-Driven)  
> **Локация проекта**: Кыргызстан (Бишкек / Аламудун / Иссык-Куль)  
> **Проект**: Экосистема автоматизированной доставки еды и B2B логистики через Telegram Web Apps & Bots.

---

## 🎯 1. Главная цель и бизнес-логика (Overview)

### 1.1. Миссия проекта
Создать максимально быструю, отказоустойчивую и полностью автоматизированную систему доставки еды и курьерской логистики внутри Telegram, исключающую рутинный ручной труд диспетчера:
- Клиент заказывает за 30-40 секунд через ультра-быстрый Telegram Web App (TWA).
- Оплата принимается автоматически через эквайринг Bakai Bank (с мгновенным подтверждением по Webhook).
- Кухня мгновенно получает звуковое уведомление в боте и нажимает «Принять в готовку».
- Система дает заказ ближаещему курьеру
- Курьеры пополняют баланс напрямую через Bakai Bank без необходимости писать администратору.

### 1.2. Роли и акторы в системе
1. **Клиент (Customer)**:
   - Вход: `@foodkg_bot` -> Кнопка Web App «🍕 Открыть меню».
   - Функции: Выбор адреса на карте Leaflet / геолокация, выбор блюд из меню ресторанов, расчет доставки, ввод контактов, онлайн-оплата картой / кошельками через Bakai PayLink, отслеживание  и получение уведомлений о статуса заказа и об курьере который везет его еду.
2. **Ресторан / Кухня (Partner)**:
   - Вход: `@tamak_restaurant_bot` + Web App панель (`restaurant_panel.html`).
   - Функции: Управление стоп-листом и добавление блюд в меню, передача геопозиции заведения, получение заказов с кнопками «👨‍🍳 Принять и начать готовить» / «❌ Отклонить», ручной вызов курьера для сторонних заказов (`partner.html`).
3. **Курьер (Logistics)**:
   - Вход: `@bizjumush_bot` + Web App пополнения (`courier_pay.html`).
   - Функции: Регистрация (отправка контакта), выход на линию через Live-геолокацию Telegram, принятие или отказ от заказа, маршрутизация в 2GIS через ссылку полученной от клиентского бота, ведение статусов «В пути» -> «Доставлен», списание комиссии 10% (или 20 сом за ручной), моментальное пополнение баланса через Bakai Bank PayLink.
4. **Администратор / Диспетчер (Admin)**:
   - Вход: Админ-группа Telegram (`ADMIN_CHAT_ID`) + мой аккаунт`@foodkgadmin`.
   - Функции: Одобрение новых ресторанов и курьеров, мониторинг оплат, ручное начисление балансов через `/pay`, связь с клиентом и рестораном в экстренных ситуациях.

## 🔄 3. Архитектура потока данных (Data Flow)

### 3.1. Основной цикл клиентского заказа
```
[Клиент в Web App]
       │
       ▼ (1) Отправка POST /web-data
[Backend Express] ──── (Проверка спама: макс 2 активных заказа)
       │
       ▼ (2) INSERT status: 'waiting_payment'
[Supabase: orders]
       │
       ▼ (3) Запрос POST /api/create-paylink
[Bakai Bank API] ────> Клиент получает ссылку и оплачивает
       │
       ▼ (4) POST /api/bakai-webhook (при успехе)
[Backend Express]
       │
       ├─► (5) UPDATE orders SET status = 'paid'
       │
       ├─► (6) Уведомление в Админ-чат
       │
       └─► (7) Отправка в Ресторан: [👨‍🍳 Принять и начать готовить]
```

### 3.2. Логистический цикл (Кухня ➔ Курьер ➔ Доставка: Модель Яндекс)
```
[Ресторан жмет "Принять"] ──► UPDATE status = 'cooking' ──► Realtime уведомление клиенту
                                      │
[Авто-диспетчер (Haversine)] ◄────────┘
       │
       ▼ Находит свободных курьеров (is_online=true, balance>0, без активного заказа)
       ▼ Сортирует по расстоянию до ресторана: [Курьер 1 (300м), Курьер 2 (700м)...]
       │
       ├─► (1) Отправка в ЛИЧКУ Ближайшему Курьеру 1 (Таймер: 45 сек)
       │       [✅ Принять заказ]   [❌ Пропустить]
       │
       ├─► ЕСЛИ Курьер 1 принял:
       │       ├─► UPDATE orders SET courier_id = courier.id
       │       ├─► В ЛС курьеру: Адрес, Состав, Маршрут 2GIS, [📦 Я взял заказ]
       │       └─► В инфо-группу: "🛵 Заказ #12345 взял Курьер (300м от ресторана)"
       │
       └─► ЕСЛИ Курьер 1 отклонил или таймер истек:
               └─► Передача Курьеру 2 (следующему по близости)
```

### 3.3. Цикл пополнения баланса курьера (Автоматизация Bakai Bank)
```
[Курьер в боте] ──► Жмет кнопку "💳 Пополнить баланс"
       │
       ▼ Открывается Web App (courier_pay.html?id=ID_КУРЬЕРА)
[Выбор суммы] (например: 100, 200, 500 сом или своя)
       │
       ▼ POST /api/generate-courier-paylink (transactionID: "COURIER" + courierId)
[Bakai Bank PayLink] ──► Курьер оплачивает
       │
       ▼ POST /api/bakaicourier-webhook (при подтверждении банка)
[Backend Express]
       ├─► Парсит courierId = transactionID.replace("COURIER", "")
       ├─► UPDATE couriers SET balance = balance + paidAmount
       └─► Отправка курьеру в ЛС: "🎉 Баланс пополнен на X сом! Текущий баланс: Y сом."
```

## 🛡️ 5. Незыблемые законы системы (Hard Constraints & Crash-Proof)

1. **State Protection (Защита от скачков во времени)**:
   - Если курьер принял заказ, а ресторан отменил его, то уведомляем курьеру, что заказ уже не актуален
   - Нельзя взять заказ если ресторан первее чем курьер не принял заказ
   - Нельзя взять заказ, если он уже взят другим курьером (`order.courier_id` уже заполнен).
   - Нельзя принять в готовку заказ, который уже у курьера (`delivery`) или завершен (`completed`).
   - Нельзя отменить заказ, если статус `completed`.
   - Любое действие обязано перепроверять текущую запись в Supabase перед мутацией!
2. **Балансовая защита курьера**:
   - Курьер с балансом `<= 0` не имеет права брать новые заказы (выводится алерт о необходимости пополнить).
   - Комиссия списывается атомарно после успешного завершения доставки.
3. **Безотказность Telegram UI (No Endless Spinners)**:
   - Любой `bot.action(...)` обязан вызывать `await ctx.answerCbQuery()`, чтобы у пользователя не зависали «часики» загрузки кнопки.
   - Любые пользовательские строки экранируются функцией `safeHtml`, чтобы спецсимволы (`<`, `>`, `&`) не роняли отправку через `parse_mode: 'HTML'`.
4. **Кликабельность контактов**:
   - Номера телефонов отдаются без тега `<code>` или внутри ссылки `tel:`, чтобы мобильный Telegram делал их кликабельными для мгновенного звонка.
   - Ссылка на клиента/курьера оформляется как `tg://user?id=XXXXX`.
5. **Мобильный фронтенд (Mobile-First >= 350px)**:
   - Никаких горизонтальных скроллов страницы целиком (только горизонтальные карусели категорий).
   - Если контент не помещается на малых экранах (iPhone SE / Android 350px) — предусмотрен плавный вертикальный скролл.
   - Sticky-панели корзины и действий с `env(safe-area-inset-bottom)`.

## 🚨 7. Обработка форс-мажоров и внештатных ситуаций (Edge Cases)

### 7.1. Сеть и связь (Проблемы с интернетом)
1. **Пропал интернет у курьера во время доставки (`delivery`)**:
   - Web App курьера кеширует текущие данные о заказе в `localStorage`.
   - При клике на «Доставлен» без связи: показывается алерт: *«Нет связи. Статус сохранился локально и отправится при появлении сети»*.
   - При восстановлении сети Web App автоматически делает повторный запрос к Supabase (`retry logic`).
2. **Сервер Render уснул / долго отвечает (Cold Start)**:
   - Web App клиента при оформлении заказа показывает анимацию загрузки (Skeleton / Spinner) со встроенным таймаутом в 15 секунд.
   - Если сервер не ответил за 15 секунд — показывается мягкая ошибка: *«Превышено время ожидания. Попробуйте еще раз»* без перезагрузки всей корзины.

### 7.2. Отмена заказов и конфликты статусов
1. **Клиент или Ресторан отменил заказ, когда Курьер уже принял его**:
   - Статус заказа в БД меняется на `canceled`.
   - Курьеру в бот `@bizjumush_bot` мгновенно прилетает приоритетное PUSH-уведомление: *«⚠️ Заказ #12345 отменен клиентом/рестораном. Не везите его!»*.
   - Кнопки взаимодействия с этим заказом у курьера при нажатии на них получает всплывающее окно-алерт прямо поверх чата Telegram ❌ Заказ #12345 отменен»
2. **Ресторан нажал «Отклонить» заказ**:
   - Статус переходит в `canceled`.
   - Клиенту отправляется сообщение в `@foodkg_bot`: *«К сожалению, ресторан не может принять ваш заказ (заведение перегружено или закончились ингредиенты). Деньги вернутся на карту»*.
   - Администратор получат уведомление в `ADMIN_CHAT_ID` для контроля возврата средств.

### 7.3. Проблемы с курьерами и балансом
1. **Курьер взял заказ, но долго не двигается (или пропал)**:
   - В будущем: Таймер на 5 минут после взятия. Если статус не сменился и нет Live-геолокации — в админ-чат уходит сигнал: *«⚠️ Курьер [Имя] не перемещается по заказу #12345»*.
2. **Баланс курьера ушел в минус или ровно 0**:
   - Система сразу переводит `is_online = false`.
   - Курьер не получает новые заказы, пока не пополнит счет через `courier_pay.html`.

## 🚀 8. Протокол авто-деплоя и Git (Auto-Push Workflow)

1. **Хостинг и непрерывный деплой (Vercel CI/CD)**:
   - Клиентский Web App (`index.html`), симулятор (`delivery_simulator.html`), панель ресторана (`restaurant_panel.html`) и оплата курьера (`courier_pay.html`) размещены на Vercel (`superkgapp.vercel.app`).
   - Деплой на Vercel триггерится автоматически при пуше коммита в ветку `main` GitHub-репозитория `edilkg/superkgapp`.
2. **Автоматический Git Push агентом**:
   - AI-агент Antigravity обязан **автоматически коммитить и пушить** (`git push origin main`) любые внесенные и проверенные изменения сразу по завершении работы над задачей.
   - Пользователю не нужно выполнять `git push` вручную. Все обновления кода мгновенно уходят на продакшн Vercel, чтобы они сразу были видны в Telegram Web App.
   - Стандартные команды авто-деплоя:
     ```bash
     git add .
     git commit -m "<структурированное понятное описание>"
     git push origin main
     ```
