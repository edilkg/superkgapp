1. Суть проекта и Технологический стек
TamakKG — автоматизированная система доставки еды в Telegram (Бишкек/Аламудун). Состоит из Web App (для клиента) и 4-х изолированных ботов, работающих через единую БД.

Frontend: HTML, CSS, JavaScript. Адаптивность под мобильные (ОТ 350px И ВЫШЕ). Хостинг — GitHub Pages / Vercel.

Backend: Node.js, Express, Telegraf (фреймворк для ботов). Хостинг — Render.

База данных: Supabase (PostgreSQL).

Realtime: Supabase Channels (динамическое обновление статусов на клиенте).

Карты: Leaflet + OpenStreetMap.

Контроль версий: GitHub (репозиторий superkgapp).

🏗 2. Архитектура проекта (Сервер + 4 Бота + Web App)
Код строго разделен на модули. Каждый отвечает только за свою зону:

server.js (Главный контроллер): API-шлюз. Принимает заказы из Web App, пишет в Supabase, контролирует лимит спама (макс. 2 заказа на юзера), запускает всех ботов.

bot_client.js (Клиент): Входная точка. Запуск Web App (index.html) через кнопку.

bot_admin.js (Центральный узел): «Судья». Одобряет/отклоняет оплату заказов, одобряет регистрации курьеров и ресторанов, пополняет балансы. Распределяет заказы дальше.

bot_restaurant.js (Кухня): Приемка или отменаа заказа в готовку и передача заказа курьеру. Имеет встроенную State Protection (блокировку кнопок, если заказ уже у курьера).

bot_courier.js (Логистика): Поиск заказов, статусы «еду в ресторан / забрал / доставил». Связь с клиентом (вывод телефона и ссылки на ТГ профиль).

index.html (Web App): Фронтенд клиента с поддержкой мульти-заказов (несколько активных баннеров на главном экране одновременно).

📱 3. Структура клиентского интерфейса (5 экранов)
Главный экран: Поле "ДОСТАВИТЬ ПО АДРЕСУ", горизонтальное меню категорий, поисковик ресторанов. список ресторанов с информацией о расстоянии, цены за доставку и ожидание до клиента. и динамические мини-баннеры активных заказов.

Экран ресторана: инфо о ресторане: (время работы. адрес),горизонтальное меню разделов меню. карточки блюд (при нажатии инфо о блюде), добавление в корзину.

Оформление заказа: Карта (Leaflet), детали доставки, приборы, комментарии. карта с адресом, доп.функция (доставка до двери). номер клиента, итоговый чек.

Экран оплаты платежная ссылка с вебхуком от bakai bank.
Экран статуса: Отслеживание заказа в реальном времени через Supabase Channels (Проверка ➔ Готовится ➔ В пути ➔ Доставлен).

🛑 4. КЛЮЧЕВЫЕ БИЗНЕС-ПРАВИЛА (Hard Constraints)
предлагай решения которые не будет нагружать систему, оптимизация наше все. чтобы у юзеро все летало.

Кликабельность контактов: Все номера телефонов в ботах отправляются обычным текстом (без тега <code>), чтобы ТГ делал их ссылкой для звонка. Профили вызываются через tg://user?id=....

State Protection (Защита состояний): Перед выполнением любого действия (одобрение, готовка, доставка) бот обязан проверить текущий статус заказа в базе. Никаких «путешествий во времени»!

## 🗄 3. База данных## 
🏢 1. Таблица restaurants (Рестораны-партнеры)Хранит данные владельцев заведений (управляется через bot_restaurant.js).  id (bigint): Telegram ID администратора ресторана.  name (text): Название заведения.  phone (text): Контактный телефон заведения.  is_approved (boolean): Статус проверки (true — одобрен админом, false — на модерации).  step (text): Техническая колонка для шагов регистрации (ask_name, ask_phone, waiting).  

2. Таблица menu (Меню ресторанов)Хранит ассортимент блюд. Web App загружает эти данные напрямую из базы для отрисовки меню.  id (uuid/int): Уникальный ID блюда.  restaurant_id (text/int): Привязка к конкретному ресторану (101, 102 и т.д.).  name (text): Название блюда.  price (int): Цена блюда.  weight (text): Вес или граммовка.  category (text): Категория для фильтров ("Бургеры", "Суши" и т.д.).  description (text): Состав или описание блюда.  img_url (text): Ссылка на фотографию блюда.  is_available (boolean): Наличие блюда (если false, оно не покажется в приложении).  🔗 Как это всё связано (Кратко)Клиент собирает корзину из menu.  Сервер создает новую строку в orders.  Админ одобряет оплату, и заказ улетает в restaurants (по названию) и рассылается всем активным couriers.  Любые изменения статуса в orders моментально отображаются у клиента в Web App благодаря технологии Supabase Channels (Realtime).  

 3. Таблица orders (Заказы)Центральная таблица, где хранится вся информация о покупках и их движении. Создается сервером при получении запроса из Web App.  
id (uuid/int): Уникальный номер заказа (выводится клиентам и админам как #12345).  
client_id (bigint): Telegram ID клиента (нужен для отправки уведомлений).  
client_name (text): Имя клиента из Telegram.  
phone (text): Номер телефона клиента для курьера и ресторана. 
 address (text): Полный адрес доставки (улица, дом, квартира).  
restaurant (text): Название ресторана, в котором сделан заказ. 
 total_price (int): Итоговая сумма заказа (в сомах).  comment (text): Склеенные детали заказа (доставка до двери, приборы, ориентир, комментарий кухне).  items (jsonb): Массив заказанных блюд (названия, количество, цена).  status (text): Текущий этап заказа. Возможные значения:  waiting_payment (ожидает проверки админом)  paid (оплачен, ждет реакции кухни)cooking (ресторан готовит)  delivery (передан курьеру)completed (успешно доставлен)canceled (отменен админом или рестораном)  courier_id (bigint): Telegram ID курьера, который взял заказ (привязывается, когда курьер жмет "Я возьму").

4. Таблица couriers (Курьеры)
Отвечает за хранение данных курьеров, их баланса и рабочего статуса.
id (int8): Telegram ID курьера (Primary Key, без автонумерации "Is Identity").
name (text): Имя курьера из Telegram.
phone (text): Номер телефона курьера.
balance (int8): Внутренний кошелек (баланс) курьера. Значение по умолчанию: 0.
is_approved (boolean): Одобрен ли курьер администратором. Значение по умолчанию: false.
status (text): Рабочий статус курьера на линии (online или offline). Значение по умолчанию: offline.
step (text): Системная колонка для бота, запоминает текущий этап регистрации курьера (например, ask_phone или completed).
